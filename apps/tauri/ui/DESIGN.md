# Familiar · 灵伴 Android 前端设计说明

本目录是 Android 端的完整前端：`index.html`、`style.css`、`app.ts`（2026-10-19 起支持七类模型、快照驱动的七位角色、已授权能力的系统设置入口、独立的跨应用悬浮审批卡片 `mountApproval`、聊天里的图片与文本附件，以及系统相机拍照入口）。没有运行依赖，也不用框架；所有业务都通过 `MobileBridge` 交给核心处理。

## 视觉

- **以桌面控制器为准**：奶油纸底 `#f6f4ec`、鼠尾草绿主按钮、橄榄色软描边、1.5px 浅描边，面板和按钮底部带一道 2px 的“贴纸底边”。颜色变量与桌面 `plugins/control-center/ui/style.css` 同名，方便以后一起调整。
- **草地小窗是主角**：桌面侧栏里的小窗放大成首页主视觉，保留轨道圈、虚线内圈、粉彩闪点和草坡。角色切换时整套 `--sky / --hill / --orbit` 一起换色（小森绿、柚子橙、月团紫）；头像、形象卡片和伙伴预览也用同一套变量。后加入的 diandian / fangfang / lili / mianmian 先按同一明度取了雾蓝、奶黄、樱粉、燕麦四种色相（没有看过这几位的角色图，Codex 可按实际角色微调 `style.css` 顶部四段变量）；界面不认识的角色沿用鼠尾草绿默认配色。
- **贴纸式导航**：底部是一条浮起的圆角导航条，选中项用鼠尾草浅底，不照搬桌面侧栏。
- 文案全部是中文口语，不出现 revision、bridge、provider 这类内部词。

## 信息架构

| 位置 | 内容 |
| --- | --- |
| **小窝**（首页） | 大号草地小窗，点一下角色会跳一下、冒出小爱心和一句本地互动短句（纯界面反馈，不是模型回复）；常驻且就绪时草坡左下角挂“常驻中”小牌子；名字和状态（问候 / 正在回复 / 没连模型 / 有几件事等你处理）；“说句话”“换个样子”；未配置模型提醒；**常驻伙伴卡片**；“等你处理”的任务卡；“上次聊到”卡片；手机能力按状态汇总（已授权 N 项 / 未授权 N 项…） |
| **聊天**（全屏页） | 顶栏：返回、头像 + 对话标题 + 状态、聊天记录、新对话。消息列表、属于这段对话的任务卡、空状态（小窗 + 开头建议，点建议只填入输入框不直接发送）。消息里的附件显示为小纸片（类型图标、名称、大小），只有附件的消息也照常显示。底部：待发送附件托盘、相机（`media.camera === true` 时）与回形针（`media.choose === true` 时）+ 输入框 + 发送/停止按钮；两个来源都有时并成一枚双格贴纸 |
| **能力**（标签页） | 按用途分组的能力卡：常驻与提醒（悬浮窗、通知、电池优化）、帮你做事（日历、笔记、文件、无障碍）、相机、语音与位置（相机、麦克风、位置），界面不认识的新能力进“其他”。每张卡：专属粉彩图标、状态标签、核心给的说明、`去授权 / 去系统设置 / 重新连接`（只在核心状态允许时出现）、详情弹层（授权说明 + 授权方式）；快照里缺的已知能力只在末尾写“这个版本还没有提供：…”；下方是全部任务记录 |
| **设置**（标签页） | 伙伴（形象、昵称、性格）→ 全屏表单；常驻（常驻伙伴状态 → 跳回小窝的常驻卡片；悬浮窗与后台授权 → 能力页）；模型连接（显示“类型 · 模型”）→ 全屏表单；关于（说明数据由灵伴保管、当前模式） |
| **伙伴**（全屏页） | 顶部草地小窗预览 + 名字 + 所选形象的完整介绍；下方“选一个形象 · 共 N 位”。手机上是一排可横向滑动的形象架（露出半张卡提示可滑，打开时把已选形象滚到中间），平板上换行成网格；卡片只放头像和名字，已保存的那位挂“现在”小牌子，选中的打勾。数量、名字、介绍和图片全部来自 `snapshot.characters`，不写死任何一位 |
| **模型连接**（全屏页） | 当前连接状态卡（正在使用：类型名 · 模型 · 密钥情况）；回复中提示；“模型类型”两列贴纸小卡（平板三列），每张有首字母色块、名称、“已保存密钥 / 需要密钥 / 可以不填密钥”，正在使用的挂“使用中”；地址、模型、密钥表单；清除密钥；底部保存（查看其他类型时为“保存并改用”） |
| 弹层 | 聊天记录（选择 / 新建 / 删除）、能力详情、附件预览、删除与清除密钥的二次确认、无障碍开启前确认、有回复或任务进行中时的停止常驻确认 |

导航用一个层栈 + `history.pushState`：打开页面或弹层会压一层，Android 返回键 / 浏览器后退 / Esc / 界面上的返回按钮都走同一路径，先关最上面的弹层，再关页面，再从“能力/设置”回到小窝；能力和设置之间切换不叠加历史。关闭后焦点回到打开它的那个控件。下层内容加 `inert`，读屏和键盘不会跑到弹层后面。宿主若没派发 `popstate`，350ms 后自行关闭这一层，返回按钮不会失灵。

## 交互细节

- **流式不丢输入**：骨架只建一次，快照到来时按 id 复用消息、任务、能力、历史节点，只改变化的文字。输入框、表单从不因为快照重建。快照用 `requestAnimationFrame` 合并，一帧只渲染一次。
- **滚动**：停在底部时跟随新内容；用户往上翻时不打扰，出现“回到最新”按钮。
- **发送**：回车默认换行，只有点发送按钮（或外接键盘 Ctrl/⌘+Enter，且输入法组字中不触发）才发送。`message.send` 携带点击那一刻的 `activeConversationId`（`null` 表示由核心原子新建会话再发送）和那一刻托盘里的附件 id（没有附件时不带 `attachments` 字段，旧宿主不受影响）；只有附件、没有文字也可以发送。“再发一次”同样如此，并带上原消息的附件；快照已变但界面还没切过去的那一帧不发送。回复进行中发送按钮换成停止按钮。最后一条回复失败时显示“再发一次”。
- **按会话隔离草稿**：文字草稿和待发送附件一起只在内存里按会话 id 保存（“还没有会话”单独一份）。切换会话时把输入框和托盘存进原会话、换上目标会话的；只有会话 id 变化才动输入框，连续快照不会打断组字或输入。发出时只清空所属会话的输入和托盘；之后新写的字、新加的附件不会被发送成功清掉。失败时原话和原附件放回它所属会话——文字：那段会话正在看且输入框为空才填回，不在看且没有已存草稿才存入，已有新内容一律不覆盖；附件：与那里新加的合并，按 id 去重，发送期间新加的保留在前、原附件补在后，总数不超过上限（超出时提示几个原附件没能放回）。以 `null` 发出后核心新建的会话被视为同一段延续，期间写的下一句、加的附件随之保留。删除会话时丢弃它的文字和附件草稿。
- **图片与文本附件**（`snapshot.media`、`media.choose`、`media.preview`）：
  - **入口**：输入框左侧一枚回形针圆钮（可访问名称固定为“添加图片或文本文件”），只在 `media.choose === true` 时出现；快照没有 `media` 时不出现入口，空状态文案也不提附件。没有录音、截图入口。
  - **系统相机**（`media.camera`）：回形针左边一枚相机圆钮（“用系统相机拍照”），只在 `media.camera === true` 时出现；缺失或 `false` 时不显示，**不根据 `files` 能力或 `media.choose` 推断**。两个来源都在时并成一枚胶囊形双格贴纸，中间虚线分格，每格仍是完整 48×48；只有一个时就是单枚圆钮。点击调用 `media.camera`，由系统相机处理拍照和相机权限；确认后的照片只加入当前会话的待发送托盘，仍须点发送才交给所选模型。取消返回 `[]` 时什么都不动；失败按错误码提示“没能拍照”（`INVALID_INPUT` 说明照片大小上限）。
  - **共用一把锁**：相机和文件选择共用同一个“正在选择”锁、会话归属、8 项总数、大小限制、去重、失败恢复和本地预览规则。任一来源打开期间两枚按钮都禁用，只有被点的那枚闪烁并改读屏名称（“正在打开系统选择器… / 正在打开系统相机…”）；托盘满时两枚都禁用并说明先移除一些。回来后焦点回到刚才点的那枚按钮。
  - **选择器归属**：点回形针或相机时记下当时的会话（以 `null` 发送后被核心新建的会话视为同一段，归属随之改过去），选择期间按钮禁用并闪烁，不会重复打开。回来时即使已经切换会话，选好的附件也只放进原会话的待发送里（并提示“已放进原来那段对话”）；原会话已被删除则不加并提示。取消返回 `[]` 时什么都不动；选择失败只给提示，文字草稿、已有附件和进行中的回复都不受影响。
  - **限制**：上限优先用 `media.maxAttachments / maxBytes / maxTextBytes`，缺省为 8 个、图片 12 MiB、文本 400000 字节。超大的文件不加入并说明限制，超过个数的部分不加入并说明数量；按 id 去重。托盘满了回形针禁用，读屏标签说明“先移除一些再添加”。
  - **托盘**：输入框上方一排可横向滑动的小纸片——图片用缩略图（只为托盘里的图片按需取一次 `media.preview`），文本用纸张图标，配名称和大小；右侧 48px 的 × 移除，移除后焦点落到相邻附件或输入框。托盘头写“待发送 N/8 · 只存在手机里，点发送后才交给模型”。有附件时输入框占位文字改为“可以只发附件，也可以再说点什么…”。
  - **聊天记录**：按 `MobileMessage.attachments` 渲染附件纸片，只放类型图标、名称和大小，**不预取任何历史图片**，点开才读取预览；没有文字的消息不留空行。附件按 id/名称/大小签名比较，流式快照不会重建它们。聊天记录列表和“上次聊到”的摘要在只有附件时写“［图片］名称 / ［N 个附件］”。
  - **预览弹层**：标题是文件名，下方“类型 · 大小 · MIME”。`dataUrl`（只接受 PNG/JPEG/WebP/GIF 的 base64 data URL）显示为图片并注明“大图可能是缩小后的预览”；`text` 放在 `<pre>` 里按纯文本显示并注明“可能只包含开头一部分”；都没有或图片加载失败时只显示类型图标和“没有可显示的预览”；读取失败给出按错误码的提示和“再试一次”。从托盘打开时说明“只存在手机里，点发送后才会交给当前模型”，并可“不发送这个附件”；从聊天记录打开时只读。走同一个层栈，返回键/关闭按钮关闭后焦点回到原纸片。关闭即作废还在路上的预览结果并释放图片。预览结果只在内存里缓存最近 24 项。
  - **安全**：文件名、MIME、文本内容全部用 `textContent` / 属性写入，从不 `innerHTML`；不打开任何外部链接，不读写本地存储。
- **忙碌保护**：每个动作有自己的 pending key（发送、停止、新建、切换、选择附件、各任务、各能力、保存、确认框），进行中重复点击直接忽略，按钮禁用。
- **错误**：只按错误码映射成友好中文（连不上、内容不对、正在忙、找不到、保存出错、模型没回应），从不显示原始 `message`，避免泄露密钥或网络响应。表单错误显示在表单底栏，其它错误用顶部提示条。
- **表单**：打开页面时从快照回填；用户改过之后不再被快照覆盖；保存成功后只接受保存之前 revision 之后的快照回填。页面关闭会作废迟到的保存结果，迟到响应不会写进已关闭或重新打开的表单。
- **密钥**：密码框，可切换显示。点保存时读取一次、立即清空输入框，只放进这一次 `provider.save` 的参数；不回填、不写日志、不进任何存储，页面关闭和卸载时也会清空。保存失败时不断言密钥是否已写入（超时可能已保存、只是结果丢失），提示先看连接状态再决定是否重新保存，界面不会自动重试。
- **七类模型**（`snapshot.providers`）：
  - 打开页面时停在正在使用的类型（`provider.kind`，缺省视为 `compatible`）。点另一张类型卡只是“查看”，表单换成**该类型自己的 `profile`**（地址、模型），密钥输入一律清空；在本次打开期间改过但未保存的地址/模型按类型暂存在内存里，切回来还在，关闭页面即丢弃；密钥从不跨类型保留，也从不回填。名称、`requiresKey` 都以快照为准，类型列表靠 `reconcile` 渲染，不写死七项。
  - 提示文字写明“现在仍在使用 A，点保存并改用后才换成 B”；保存时提交 `{ kind, baseUrl, model, apiKey? }`，成功提示“之后改用 B 聊天”。
  - **密钥按类型 + 地址隔离**：`profile.keyConfigured` 只对它保存的那个地址成立。地址框一改（忽略首尾空白和末尾斜杠后不同），提示立刻变为“新地址还没有保存过密钥，原地址的密钥不会发给新地址”；`requiresKey` 的类型换了地址又没填密钥时不提交，请用户重新填写。界面从不把旧密钥带到新地址。
  - “清除密钥”只对正在使用的类型、它已保存的地址提供，二次确认里写明是哪一种、哪个地址，其他类型和地址不受影响；发送 `{ kind, baseUrl, model, clearApiKey: true }`，地址和模型取核心当前值而不是表单草稿；确认期间正在使用的类型变了就不清除。
  - **忙碌保护**：保存中类型卡和保存按钮禁用；回复进行中保存、清除密钥都禁用，并在页内说明“等这句说完或停止后再保存”。迟到的保存结果按页面 token 丢弃；保存期间又切换类型或改过内容，表单保持未保存状态。
  - 旧快照没有 `providers` 时不显示类型区，也不发送 `kind`，其余行为同上（包括换地址后的密钥提示）。
- **任务卡**：按核心状态显示“等你确认 / 正在执行 / 等你操作 / 已完成 / 已停止 / 没有完成 / 结果未知”。四种 `kind` 各有标签、图标、预览小标题和逐状态说明（`TASK_KIND`）：
  - `calendar` 日历 / `notes` 笔记：预览为“将要写入日历/笔记的内容”，结果未知时提示打开对应应用核对。
  - 2026-10-20 创建日程预览由核心提供中文计划：日历编号、标题、首次起止/全天日期、时区、重复频率/星期/次数或截止、地点和备注；无限重复明确显示，保留飞书来源。仍使用相同可滚动纸片和固定批准按钮，提醒是否实际响铃不作成功承诺。
  - 同日改删预览明确显示“整个重复系列”或“仅这一次”，列出原定/当前/新时间、改动内容、例外数量与整组删除影响。系列重排包含历史日期；已有例外会拒绝重排。单次变更需系列具有同步标识，取消恢复交给日历应用。界面继续只呈现核心任务，不推断可写性、不代替日历决定操作范围。
  - `accessibility` 手机操作（真实共享 Agent 请求代你点击、输入、滑动）：预览为“它打算在手机上做的操作”，说明“批准后才会代你点击、输入或滑动”，结果未知时提示看手机上的实际情况。
  - `tool` 工具（通用工具批准）：预览为“它打算做的事”，说明“批准后才会执行”。界面不认识的新 `kind` 也按“工具”显示。
  - 所有种类操作一致：等你确认时“批准 / 不用了”，执行中“停止”，等你操作时“取消”，全部走 `task.respond({ id, action: 'approve' | 'stop' })`；按钮 `aria-label` 带上任务标题。界面从不自己推进状态。
- **能力**：严格显示核心给的四种状态，未知状态按“暂不可用”处理；“暂不可用”没有按钮，界面不会假装能开启未实现的能力。授权按需发起，启动时不弹任何授权，每项都可以拒绝；说明区分两种方式：系统弹窗（通知、日历、麦克风、位置）和需要用户到系统设置页亲自打开（悬浮窗、电池优化、无障碍），按钮文案相应为“去授权 / 去系统设置”，未授权和已断开用主按钮。
  - **已授权也有系统设置入口**：悬浮窗、通知、电池优化、日历、麦克风、位置、无障碍在已授权时，卡片上是次要样式的“系统设置”，详情里是“在系统设置中查看”，调用同一个 `capability.request`，由宿主打开对应设置页。文案只说“打开设置页、要不要关闭由你决定、回来后按实际状态显示”，不说点击会改变授权。
  - **笔记、文件、相机不放按钮**：它们不经 `capability.request` 申请，任何状态都不显示授权或设置按钮，只按状态给说明（已可用 / 用到时按需询问 / 暂时连不上 / 不支持）。相机单独说明：只是调用系统相机，相机权限由系统相机自己询问，拍好的照片点发送后才交给模型，灵伴不会自己在后台拍照；暂不可用时说明聊天里不会出现拍照按钮。文件和相机都不请求全部存储访问。
- **无障碍**：卡片和详情里写明“能读取当前屏幕上显示的内容，并可以代你点击、输入和滑动；某一步经你批准后，还可以采集当前应用的画面交给你选的模型，不会在后台持续录屏”，开启前的确认框也写明这一点；手机操作任务卡的“等你确认”说明同样提到采集画面。截图只由受控工具在批准后触发，界面没有手动截图按钮或自动截图设置。未授权或已断开时点“去系统设置 / 重新连接”先弹确认框，用户确认后才调用 `capability.request`，真正的开关由 Android 系统设置页完成；已授权时“在系统设置中查看”直接打开设置页，不再弹申请说明。不说是自动获取权限，也不说专为某类人群设计。
- **常驻伙伴**（`snapshot.runtime`）：小窝里一张独立卡片，标题旁的状态标签由 `running + engine` 组合得出（未开启 / 正在启动 / 常驻中 / 正在准备 / 出了问题 / 没能启动），下面三行分别是“后台陪伴（运行中/已停止）”“伙伴状态（正在醒来/已就绪/休息中/出了问题）”“桌面悬浮窗（显示中/未显示，未授权时附带悬浮窗的授权状态）”，再显示核心给的 `detail`。悬浮窗与常驻分开：悬浮窗、通知、电池优化未授权或断开时出现对应的提示条，点“去授权”打开该能力的详情弹层，而不是直接申请。
  - 开关只发 `runtime.set({ enabled })`，从不根据点击自行宣布已开启/已停止：请求中按钮为“正在开启… / 正在停止…”；请求成功后记下目标和点击时的 revision，直到**比它新的快照**体现出来（开启：running 或 starting 或 failed；停止：不再 running）才恢复按钮，期间提示“已经告诉手机了，正在等它确认…”。15 秒仍未体现就放开按钮，提示“手机暂时没有回应，上面显示的是目前的实际状态”。失败只按错误码提示。
  - `runtime.set(false)` 会取消当前回复与等待批准的当前轮任务。停止时如有正在进行的回复、等你批准的任务（`awaitingApproval`，含手机操作和工具批准）或执行中/等你操作的任务，先弹确认框分别写明“回复会中断、N 件等你批准的事会取消、N 件任务会停止、悬浮窗会收起”；都没有则直接停止。卡片底部常驻说明“停止常驻会一并停下回复、等你批准的事和后台任务”。
  - 折叠说明“后台总被系统关掉？”：说明小米等手机的后台限制属于系统策略，可在系统设置里允许自启动、取消省电限制，但不保证永不被关闭。
  - 实际状态变化时读屏朗读一次“常驻伙伴：××，悬浮窗××”。快照没有 `runtime`（旧版预览）时卡片、草坡小牌子和设置里的“常驻”分组都不显示，其它功能不受影响。
- **预览模式**：`snapshot.mode === 'preview'` 时顶部常驻蜂蜜色横幅“预览 · 示例数据”；真实模式完全不显示。两种模式走同一套渲染代码。

## 跨应用悬浮审批卡片（`mountApproval`）

一个独立的小表面：原生悬浮窗盖在其他应用上方时，一次只请你确认一件事。它和主界面没有共用的状态，也不读取主界面的任何数据。

- **构图**（约 336×420，最窄 280）：卡片铺满悬浮窗，不带主界面的外框、导航，也没有强制的最小高度。顶部是一条 56px 的草地抬头：“f.”小标、“灵伴想请你确认”、剩余数量（“还有 N 件在后面排队 / 只有这一件”），右侧是带文字的“收起”。中间是可滚动的内容区：种类图标与名称（日历 / 笔记 / 手机操作 / 工具，沿用主界面的 `TASK_KIND`）、“等你确认”标签、完整标题、预览小标题、虚线纸条里的完整详情、这一类任务的说明，最后一行写明收起的含义。底部固定两枚 48px 按钮：“拒绝这一步”（次要、砖红字）和“允许这一步”（鼠尾草主按钮），上方是一行状态/错误。≤300px 时按钮去掉图标、收紧边距。
- **任务内容只当纯文本**：标题、详情都用 `textContent` 写入，详情 `pre-wrap` 保留换行，不截断、不省略、不改写参数；详情为空才显示“没有附带更多内容”。内容可以选中查看。
- **选哪一件**：只看 `status === 'awaitingApproval'` 的任务。正在显示的那件只要还在等批准就一直显示它，不因列表顺序变化跳走；它被移走后自动换下一件，没有就显示“都处理好了”。在主界面处理或取消的任务也只是随新快照消失。
- **防误触**：每换上一件任务（包括卡片刚出现时），按钮先锁 600ms，免得本来点向下层应用、或连点上一件时误批了新任务。界面从不自动批准。
- **回应**：点按钮调用 `respond(id, 'approve' | 'stop')`；提交中两枚按钮都禁用、被点的那枚显示“正在允许… / 正在拒绝…”。成功后不自行宣布结果，显示“已经告诉灵伴了，正在等它确认…”并保持禁用，直到快照把这件任务移走；15 秒仍未移走就放开按钮，提示“暂时没有收到确认，这一步仍在等你决定”。失败按错误码给出简短可重试的提示（`NOT_FOUND` 说“可能已经在灵伴里处理过了”），不显示原始错误内容；回应返回时卡片已换成别的任务，就丢弃这次结果。
- **收起**：顶部“收起”和空状态里的“收起”只调用 `close()`。文案写明“收起不会批准，也不会拒绝，这一步会继续等你；点一下桌面上的伙伴可以再打开”，从不说“取消”。
- **不抢焦点、不要输入**：不自动聚焦任何控件，不监听键盘，没有输入框，也不申请任何权限。读屏用一个 polite 区域朗读“灵伴想请你确认：标题”和“都处理好了”；按钮 `aria-label` 带上任务标题。
- **快照**：`subscribe` 后按 `revision` 丢弃旧快照，`protocolVersion !== 1` 时显示版本不一致；订阅失败显示“没有连上灵伴”。第一份快照到来前显示“正在读取…”。

```ts
import { mountApproval } from './app.js';
const dispose = mountApproval(approvalBridge); // 返回卸载函数
```

挂载时沿用 `#familiar-root`（没有就在 `body` 下创建），把根节点的 `app` 类换成 `approval`，并在 `<html>` 上设 `data-surface="approval"` 让页面背景透明、只露出圆角卡片；卸载时取消订阅、清除计时器和待执行的帧，恢复根节点原来的类名并清空内容，移除 `data-surface`。只用 `subscribe / respond / close`，不读写任何存储、不碰原生对象。

接口缺口：`MobileApprovalSnapshot` 没有当前伙伴的形象和名字，卡片只能用“灵伴”和小标，不显示角色图；`subscribe` 同样没有断开回调；`respond` 成功是否保证随后发布移除该任务的快照没有写明，界面以 15 秒为限。

## 如何接桥

```ts
import { mountApp } from './app.js';
const dispose = mountApp(bridge); // 返回卸载函数
```

- `app.ts` 没有顶层副作用，导出 `mountApp(bridge)` 和互不相干的 `mountApproval(approvalBridge)`（见上一节），都返回卸载函数。类型只用 `import type` 从 `packages/mobile-contracts/index.ts` 引入，运行时不依赖该文件。
- 根节点：`#familiar-root`（`index.html` 已提供，挂载前显示启动画面）；找不到时自动在 `body` 下创建。
- 启动顺序：先 `subscribe`，再 `request('snapshot.get')`；`protocolVersion !== 1` 或 `revision` 不比当前新的快照会被丢弃。读取失败时首页显示“没有连上灵伴”和重试按钮，不会伪造任何回复。
- 卸载：取消订阅，移除 window / document / visualViewport 监听，清除所有计时器和待执行的帧，清空密钥框和根节点。
- 用到的命令：`snapshot.get`、`companion.save`、`provider.save`、`conversation.create/select/delete`、`message.send`、`media.choose`、`media.camera`、`media.preview`、`reply.cancel`、`runtime.set`、`capability.request`、`task.respond`。
- 错误识别靠 `error.code`（对 `MobileBridgeError` 做鸭子类型判断），所以预览适配器和真实核心抛出相同结构即可。
- 角色图片优先用快照里的 `image`：只接受相对路径或 `http(s)/asset/tauri` 地址（不含空白、引号、尖括号，不以 `//` 开头），否则回退到 `./characters/<id>/idle-0.svg`（id 只允许字母数字、`_`、`-`）。
- 没有写 CSP meta，以免挡住 Tauri 的 IPC，CSP 交给 Tauri 配置。

## 适配

- 360 / 390 / 430 宽为单列；≥720（含 768 平板）首页变为“小窗 | 卡片”两列，全屏页面居中最宽 760，底部弹层变为居中对话框，导航条居中最宽 480，形象架换行成网格、模型类型三列；≤374 时收紧边距，形象卡收窄到 96px、类型卡色块缩小。
- 所有可点控件至少 48px；字号 15px 起，输入框 16px，避免系统自动放大。
- `viewport-fit=cover` + `env(safe-area-inset-*)`；预览横幅出现时由横幅吸收顶部安全区。
- 软键盘：`interactive-widget=resizes-content`，并用 `visualViewport` 的高度和偏移设置根节点，输入栏始终贴在键盘上方；键盘弹起时若原本停在底部会继续贴底。
- 长中文：全局 `overflow-wrap: anywhere`，消息 `pre-wrap`，标题单行省略。
- 可见焦点环（2.5px 橄榄色）；所有输入都有 `<label>`；图标按钮都有 `aria-label`；消息列表为 `role=log`，流式期间不朗读每个字，回复结束时按那条消息最终的 status 朗读一次：完成为“××回复好了”，停止为“回复已停止”，失败为“回复没有完成”，查不到结果时只说“回复结束了，请查看结果”。
- `prefers-reduced-motion` 时关闭全部动画和平滑滚动。

## 接口缺口（未绕过核心，请 Codex 评估）

1. `conversation.create` 没说明是否会自动选中新对话；界面在 create 之后会再调用一次 `conversation.select`。
2. `MobileTask` 没有时间字段，无法插进消息时间线，目前统一放在该对话消息之后。
3. 失败消息没有错误码，只能显示“这条回复没有完成”；“再发一次”是重新 `message.send` 上一句用户消息，会产生一条新的用户消息。建议增加 `message.retry`。
4. ~~没有“打开系统设置”的命令~~：已授权的系统权限现在对同一个 `capability.request` 发起，**假定宿主在已授权时打开对应的系统设置页**、不弹申请、不改状态。契约注释里没有写明这一语义，请 Codex 确认或补一个 `capability.openSettings`；若宿主对已授权项不做任何事，按钮会没有反应。
5. 已补 `provider.models/inspect/test/test.cancel`，可获取、搜索和选择模型，也可继续手填；测试限已保存配置。
6. 昵称、性格的长度上限不在契约里，界面暂定 40 / 2000 字，超限以核心的 `INVALID_INPUT` 为准。
7. `subscribe` 没有断开或错误回调，真实模式下中途失联时界面无法提示，只能等下一次请求报 `UNAVAILABLE`。
8. `message.send` 以 `null` 发送时不返回新会话 id，界面只能把“从无会话切到发送前不存在的会话”当作这次发送新建的会话。建议结果里返回 `{ conversationId }`。
9. ~~`runtime.set` 停止时会停下哪些后台工作~~：已明确会取消当前回复与等待批准的当前轮任务，确认框已计入 `awaitingApproval`。契约注释里仍可补写这一点。
10. 没有“打开自启动 / 后台限制设置”的命令，小米等系统策略只能文字引导；悬浮窗是否显示也没有单独开关，界面只展示 `overlayVisible`。
11. `runtime` 没有失败原因码，`engine: failed` 时只能显示核心给的 `detail`。
12. `provider.save` 是否总会把所提交的 `kind` 设为当前使用的类型，契约没写；界面按“保存即改用”设计。也因此“清除密钥”只对正在使用的类型提供（否则清除别的类型的密钥可能顺带切换类型）。若需要清除未使用类型的密钥，建议增加 `provider.clearKey({ kind, baseUrl })`。
13. `profile.keyConfigured` 仍只对应已保存地址；模型管理扩展通过 `provider.inspect` 查询正在填写的类型与地址，确认已存密钥后允许留空复用，查询前保持保守提示。旧宿主保留原行为。
14. 界面无法区分 `profile` 是用户保存过的还是核心默认值，所以地址说明写成“常用地址，一般不用改”。如需区分，可加 `profile.saved: boolean`。
15. `requiresKey: true` 的类型换了地址又没填密钥时，界面直接拦下不提交；核心仍应自行拒绝把旧密钥发往新地址，不能只依赖界面。
16. 四位新角色的配色是按名字猜的；`MobileCharacter` 若能带 `palette`（sky / hill / orbit），界面可直接使用，不必在 CSS 里按 id 维护。
17. `media.choose` 选出超过大小限制或不支持的文件时，是由核心直接剔除、整体报 `INVALID_INPUT`，还是照常返回？界面两种都兼容：返回的超限项不加入并说明，`INVALID_INPUT` 提示“只能选图片或文本文件”及大小限制。
18. 待发送附件只在界面内存里，界面没有“放弃导入”的命令；移除或会话删除后，核心媒体库里已导入的文件如何回收需由核心决定。`message.send` 失败时附件 id 是否仍然有效也请核心保证（界面会把它们放回草稿等待再次发送）。
19. “再发一次”会用原消息的附件 id 重新发送，假定这些 id 在媒体库里长期有效。
20. `camera` 能力的四种状态对应什么没有写明（例如 `notGranted` 是否只表示系统相机还没被允许）；界面只把它当作说明，是否显示拍照按钮完全以 `media.camera` 为准。
21. `media.camera` 在系统相机被拒绝权限时，是返回 `[]` 还是报错，契约未写；界面两种都兼容（`[]` 不做任何事，报错按错误码提示）。

## 尚未接入的原生能力

界面没有自己申请 Android 权限、调用系统 API、启动服务，也没有存储任何业务数据。常驻服务、悬浮窗以及十项能力（悬浮窗、通知、电池优化、日历、笔记、文件、无障碍、相机、麦克风、位置）的授权与执行全部由核心通过 `runtime.set` / `capability.request` / `task.respond` 和快照状态完成；手机操作（`accessibility`）和通用工具（`tool`）任务同样只展示核心给的内容，由用户批准或停止。位置目前只有授权展示，定位交互尚未接入；聊天附件通过 `media.choose` 调起系统选择器、`media.camera` 调起系统相机（都由宿主处理，界面不申请任何权限），附件支持图片和文本，语音交互见下文；屏幕画面采集只在无障碍任务批准后由受控工具触发，界面没有截图按钮；主动关怀、记忆等桌面能力也暂不展示入口。

## 语音增量（2026-10-19）

Claude 额度用尽后由 Codex 按用户授权接手。聊天输入上方并排放置“录音转文字”与“连续语音”，区分回填草稿与直接对话。全局淡绿状态条独占布局空间，保留完成录音/停止入口，不遮挡输入区；状态来自共享核心快照。单条已完成回复提供朗读。

设置以可折叠语音连接面板分开识别与朗读档案；各自地址、模型、密钥与清除，朗读另有音色、速度和流式开关。活动语音期间禁用表单；改动后不再把原地址密钥状态当成新地址状态。权限只通过核心申请，授权后需再次手动开始。迟到识别结果按 ID 只追加原会话草稿，保留文字/附件，首快照旧结果不重放。连续语音要求停止后再切换/创建/删除/发送，核心同时执行保护。未提供原生唤醒、系统音色或 Live 入口。

## 宠物停靠增量（2026-10-19，Codex）

设置中的“悬浮宠物与停靠”折叠面板延续纸底与鼠尾草绿，分开宠物设置和 Android 停靠偏好。吸附与闲置收起有两个独立开关，等待时间 10–300 秒；关闭吸附后保持自由位置。保存确认来自核心，未保存的编辑不被轮询快照覆盖。
