# 图片、语音与宠物声音

本页能力自 [v0.3.0](releases/v0.3.0.md) 起随发行包提供；v0.2.0 不包含。

2026-10-11 第一批改造已实现 Live 接入提示/预检、持续模式、有限的唤醒音频交接和可选识别提示；路线与推荐型号见 [Live 语音改造方案](16_Familiar_Live语音改造调研与实施方案.md)。**下文记录当前实现**；原生模型直接交流、无缝首句交接和会话恢复尚未落地，不以设计覆盖实际状态。

## 使用

控制器「图片与语音」独立管理这些设置，不替换「模型连接」中的主模型。

- 输入条和历史会话可添加图片、PDF、Word、文本；输入条也可粘贴图片。每条最多 8 个附件，单文件最多 12 MB。图片缩放到最长边 2560，PDF 最多 100 页、只提取文本；扫描件请转图片。文件过长明确提示拆分，不静默截断。
- 主模型需支持图片。开启「允许询问时截图」并选择显示器后，提到屏幕、桌面或关卡会附加当前截图，模型也能调用 `desktop_snapshot`。手动截图按钮只授权本次。不持续采集、录屏或上传桌面视频。
- 麦克风按钮用于录音转文字：结束后文字进入输入框，仍可编辑，再自行发送。
- 「常规语音 · 主模型与宠物声音」：识别 → 主模型 → 朗读。主模型边输出、声音边按短句合成，最多预取下一句。默认启用 PCM 流式播报，收到第一段音频即可播放，无需等整句下载完。接口不支持时可关闭；接口直接返回完整音频时按完整音频播放。该模式继续在有限范围内优化，但无法提供同等低延迟的原生 Live 同时听说体验。
- 当前 OpenRouter 识别适配仍在用户停顿后上传整段录音，不是逐字增量识别。播放中麦克风保持打开，连续约 200ms 的有效声音触发打断，同时取消主模型、合成请求和排队音频。连续对话不要求使用 OpenAI/Gemini 原生 Live。
- 文字消息只有开启「文字消息也自动朗读回复」才会自动播放。气泡和历史中的朗读按钮可手动播放。关闭气泡只控制显示，不等于结束语音；停播/结束语音按钮控制声音。
- 唤醒默认使用宠物名字；可自定义一个或多个关键词，例如「小森」「火火」。名字前后允许说别的话，不把「起床了」写死为必需命令；前后用 SAPI 通配（垃圾模型）而非自由听写，真实麦克风下听写会吞掉整句、名字置信度跌到 0.3 以下被拒。单喊名字只进入监听；带前后文且有音频时，在内存交接最多 8 秒的已识别片段，通配文本不作为原话。Windows 中文语音识别器在本机处理待机唤醒；没有识别器时保留手动开始。
- 灵敏度 0—100，默认 50；高值降低识别置信度门槛。它不是麦克风增益。连续会话内停用待机唤醒识别，请求 AEC、降噪和自动增益。默认“唤醒后持续对话”直到手动结束；关闭后才按原有空闲时间（默认 30 秒，可设 5—600 秒）回待机。用户说话与模型工作期间不计空闲。旧配置缺少 `continuous` 字段时默认开启，显式关闭则保持关闭。
- 识别接口可选填语言（中文可填 `zh`）和名字/专有词提示，最多 500 字；留空不发送这些参数。接口不支持时清空即可恢复旧请求。提示不保证准确率提升，需使用实际录音评测。

设置页显示待机麦克风当前音量、峰值和识别结果，便于区分没有输入、听见声音但未识别到名字、命中名字后对话失败。命中名字后立即显示「在呢，正在听你说。」；已识别片段尽量交接，仍不保证麦克风切换期间无缝捕获，音频不可用时请继续说具体需求。保存设置或重启监听时，旧识别进程的回调不能覆盖新状态。

更新源码前先退出宠物，再构建并重启 Runtime 与 Controller。只更新控制器会造成旧 Runtime 拒绝新命令；设置页提供明确错误与重新载入入口。

## 声音身份与性格

音色不属于主模型。声音档案保存原创参考音频、准确转录、创作描述和摘要，位于 `assets/voices/manifest.json`。当前两套声音由 Qwen 官方公开 VoiceDesign 演示按项目自有描述生成，不模仿真人：

| 声音 | 特征 | 推荐性格 |
| --- | --- | --- |
| 森铃 | 清亮柔软、轻盈的小精灵 | 温柔、热情、简洁 |
| 团团 | 圆润耐心、清透的小伙伴 | 细致、直白 |

用户可以固定一套声线，或按性格推荐。性格首先影响主模型措辞、句长和表达方式；额外合成语气参数只发送给已知支持的接口，不假装所有模型接受同一参数。五段不同性格的 MP3 试听使用这两套参考声合成，随源码、构建产物和后续安装包分发。播放随包试听不会使用用户 Token；没有 API Key 时也能试听。

默认推荐 Qwen3 ASR 1.7B 识别，以及通过 OpenRouter 接入 Fish S2.1 Pro 使用固定参考声音。两者可使用用户分别保存的 OpenRouter Key。不是把两家预设音色重命名成宠物音色：合成请求附带项目自己的参考 WAV 和对应转录。

更换主模型不触碰语音配置。切换 TTS 模型时保留声音档案；OpenRouter 的 endpoints 能力必须表明支持声音克隆，否则保存失败并保留原设置。兼容接口由用户明确启用参考音频。参考声音能帮助保持声线，不能保证不同引擎生成的波形或声学细节完全一致。

OpenRouter 当前的 Qwen TTS 已实测能合成，但其端点 `supports_voice_cloning: false`。因此保留它作为用户主动选择的服务商音色模式，而不把它当作跨模型固定宠物声线的默认后端。官方完整音色列表与聚合目录不总相同：`longanlingxi` 与 `longanhuan_v3.6` 均通过短句测试，但不纳入原创声音档案。

## 原生实时接口

另有 OpenAI Realtime 与 Gemini Live 的独立连接配置、模型/音色目录或预设、音频输入输出流和工具回调。密钥留在 Runtime，隐藏语音窗口只处理麦克风和播放。

快速原生 Live 需要用户配置支持实时音频的模型、端点与必要凭据。可先配置 `gpt-realtime` 或账户开放的 Gemini Live（官方示例 `gemini-3.8-live`）；Qwen `qwen3.8-omni-flash-realtime` 和本地 MiniCPM-o 4.5 是未适配候选。推荐按钮只填草稿，不改变声音身份或保存密钥。缺少模型、官方端点 Key 或声音身份不匹配时，在开麦和连接前提示，不静默退回常规模式。

原生服务收到语音后调用 `ask_familiar`，由现有主模型负责记忆、图片和工具，再把结果交给实时模型朗读。原生音频以 PCM 片段播放；目前这条工具桥接须等主模型的完整工具结果，不能宣称已经实现主模型逐 token 向 Live 工具结果回传。连续识别与 TTS 模式则已实现主模型短句级流式朗读。

当前两个 Live 适配器未接入项目参考声。用户若使用当前开发版并保留固定宠物音色，应使用连续识别与朗读模式；选原生实时时需主动选择「服务商音色」，程序不会静默换声。这不是所有 Live 服务的固有限制：Qwen Omni 注册音色及 MiniCPM-o 参考声音候选见文档 16。OpenRouter TTS/STT 并不意味着 OpenRouter 提供 OpenAI Realtime WebSocket。

实时会话断开或服务要求重连时明确停止并保留文字会话，首版未做无缝恢复。扬声器回声、中文口音、远场唤醒和原生服务的真实网络延迟需要实际设备与对应 Live Key 验证。

## 插件与数据契约

| 插件 | 职责 |
| --- | --- |
| `media-assets` | 保存不可变附件、按引用解析二进制和文本 |
| `platform-media` | 文件选择、剪贴板、PDF/Word 提取、单次桌面截图 |
| `media-input` | 图片设置、输入准备、截图工具与命令 |
| `voice-api` | 独立配置/密钥、目录、ASR、TTS、声音档案适配与缓存 |
| `voice-windows` | Windows 本地名字唤醒与可选系统 TTS |
| `voice-session` | 连续对话状态、打断、短句队列、Live 适配、隐藏音频窗口 |

内核未加入业务逻辑。`PromptMessage` 以附件元数据持久化，发送前由路由器解析图片；图片二进制不进入聊天日志、气泡或 IPC 历史列表。Chat Completions 的工具图片放在所有对应 tool 结果之后的资料消息中；Responses、Claude 和 Gemini 使用各自图片内容结构。MCP 图片作为附件返回，不再被当 JSON 文本截断。已有文本工具权限不变。

用户目录下的 `data/voice-settings.json`、`data/media-settings.json` 独立于主模型设置；ASR/TTS/Live Key 按接口角色、种类和地址分开加密。不会发送到渲染器、普通配置、日志或项目资源。更新模型不会更改同一接口地址下的 Key。

`data/attachment-<UUID>.json` 保存附件内容，随历史持久化；当前尚无附件回收器。`audio-cache` 默认保留 7 天、上限 256 MB，设置 0 天不保留，按时限和大小清理。参考音频位于程序资源，独立于缓存。录音默认只在内存暂存，未保存到日记。音频缓存键包含文字、模型、参考音频摘要、声音身份和参数；更换参考不会误用旧音频。

录音/播放窗口使用独立生命周期，只有它可以取得音频设备权限。停止取消请求、清播放队列；旧 epoch、旧播放序号和异步解码结果不能复活已取消音频。原生 helper 由插件回收。原生播放无需控制器保持打开。

PCM 按响应头中的采样率和声道信息播放 16 位小端单声道，跨网络片段保留半个样本并拼接，不按模型名猜采样率。完整下载后封装 WAV 缓存；取消或失败不缓存半段音频。播放结束由音频窗口确认，不把网络下载结束当成播放结束。响应头无有效采样率时明确提示关闭流式播报或修正接口。

## 验证和继续开发

执行 `npm run check`、`npm run smoke`、`npm run smoke:voice`、`npm run smoke:wake`；变更历史页还应执行 `npm run smoke:experience`。测试使用隔离目录，媒体烟雾测试注入人工音频流，不采集真实用户麦克风。唤醒测试使用合成 WAV 验证名字与前后词语，不等价于真实麦克风验收。

`scripts/design-pet-voices.mjs` 是单独人工执行的原创声线创作脚本，依赖 Qwen 官方公开演示的可用性和配额。`scripts/generate-voice-previews.mjs` 用已配置的参考音频接口生成五段短试听，会产生 API 用量；普通构建绝不运行这两个脚本。不要重新生成参考声后继续使用旧转录或旧摘要。

真实验证：Qwen ASR 正确识别项目试听文案；Qwen TTS 两个中文声音返回有效 MP3；Fish 使用原创 Qwen 参考 WAV 合成中文成功。并不据此宣称声线相似度、可爱程度、真实麦克风打断或 OpenAI/Gemini Live 已人工验收。

流式播报验证：87 项测试覆盖 PCM 首块提前交付、任意网络字节对齐、采样率、取消、缓存与旧唤醒回调隔离。Electron 测试确认服务端还未发完音频时已向播放窗口交付 PCM。2026-09-26 使用已配置的 OpenRouter Fish 接口短句实测：首块 3349ms、完整下载 4426ms、109 个片段、44100Hz；这是一次接口样本，不是用户对话总延迟承诺。

后续以文档 16 的 V0/V1 为优先：实时模型直接交流、统一上下文与历史、唤醒首句交接、持续会话、已播同步和恢复。主模型增量桥接只属于代理模式的可选优化，不能继续强制所有原生 Live 交流走这条链。链式模式继续评估增量 ASR、低噪声 VAD 和声音相似度。当前仍是停顿后转写、主模型流式输出、TTS 网络 PCM 分片播放，尚无用户对本轮真实麦克风唤醒修复的确认。

真实链路测试：经用户授权后运行 `node scripts/voice-live.mjs --saved-api`。脚本复制设置、密钥和 Local State 到隔离目录，关闭副本的待机唤醒，把本机 Windows 语音合成的已知句子按真实节奏播放进替代麦克风的音频流，再走识别、主模型、合成和播放；不打开真实麦克风，会产生少量接口费用并从扬声器发声。2026-10-11 使用 Qwen3 ASR、Fish S2.1 Pro（参考声音、PCM 流式）和一个云端主模型的结果：合成到开口 3.6 秒；已知句子识别一字不差，3.3 秒出字；宠物声音合成后再识别一字不差；完整链路说完后 3.2 秒得到文字、9.5 秒主模型首字、13.4 秒开口；播放中插话 0.63 秒清空。记录见文档 05。这是单次样本，不代表真实麦克风、远场或其他模型的表现。

2026-10-11 第一批实现检查：类型检查、95 项全套测试、Windows 构建、双应用烟雾测试、Electron 语音流程及七条离线唤醒样本通过。采集块调整为约 40ms，仍未测量真实对话总延迟；测试范围和路径见文档 05。本轮未发布安装包或同步 Git。
