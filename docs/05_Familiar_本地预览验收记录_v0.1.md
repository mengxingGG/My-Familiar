# Familiar 本地预览验收记录 v0.1

日期：2026-09-17。交付性质：Windows x64 本地开发预览，尚非完整首版正式发布。

## 已交付

- 独立 Runtime 与 Controller，分别拥有单实例锁；控制器不承载模型请求或宠物生命周期。
- 最小插件内核；平台、配置域、渲染、角色包、行为、会话、LLM、气泡和控制器均作为官方插件装配。
- 两套可替换 2D 占位角色，待机、互动、拖动、等待和睡眠动作。
- 按需唤出的文字输入条、头顶流式气泡、取消、收起、草稿保留与最近回复找回。没有聊天记录页面。
- 本地设置、角色和位置恢复，近期会话上下文保存；兼容接口的模型配置与连接测试。
- Windows 便携目录 `release/win-unpacked`，主入口 `Familiar.exe`，控制器入口为同一程序加 `--controller`。

最终打包测试证据：`.artifacts/packaged-smoke-1789649574859/result.json`，同目录保留控制器、宠物、输入条、短气泡与长气泡截图，已人工检查这些截图。

窗口测试确认：

1. 模型未配置时启动宠物并加载角色。
2. 从控制器修改大小到 125%、切换角色并验证实际窗口尺寸与渲染结果。
3. 通过本地真实 HTTP SSE 请求执行连接测试。
4. 发送后输入条收起，宠物气泡持续接收文字；正常关闭控制器不取消回复。
5. 控制器重新连接并读回已保存设置；Esc 收起后草稿保留。
6. 停止回复有效；清空会话后气泡隐藏。
7. 强制结束的是控制器实际主进程，随后仍能从宠物发起新对话。
8. Runtime 重启恢复角色与设置；下一轮请求中存在之前的近期上下文。
9. 短回复使用约 340 × 146 DIP 的小气泡，长回复不截断正文、限定窗口高度并内部滚动。
10. 反复唤出文字输入条不累积尺寸漂移。

本机窗口有缩放取整误差，测试允许 1—2 DIP。显示器几何计算的单元测试不能替代真实拔屏、混合 DPI 的手工测试。

## 本轮修复的运行问题

- 退出请求等待启动过程结束后再逆序释放插件，避免启动/退出交错留下窗口和进程。
- 输入条与气泡没有常驻动画，对它们关闭后台帧节流，解决隐藏后再激活时输入窗口渲染无法及时恢复的问题；宠物动画仍保留后台节流。
- Windows 不可调整尺寸的窗口会锁定最小/最大尺寸。透明浮层改为允许程序调整尺寸，并拦截手动拉伸；定位使用位置更新，防止覆盖刚调整的尺寸，并避免反复处理 1 DIP 的取整差异。API 行为参考 [Electron BrowserWindow 官方文档](https://www.electronjs.org/docs/latest/api/browser-window)，具体结果以上述本机窗口断言为准。
- 清理构建输出后再复制 UI，打包产物不再残留旧聊天页面。

## 尚未完成的验收

- 尚未配置或请求真实 LLM 供应商；模拟接口通过不等于供应商集成验证通过。当前仅消费兼容流式接口的 `delta.content`，忽略单独的推理字段。
- 中文字符串发送已验证；中文输入法候选选择、实际组合输入仍需手工验证。
- 多实体显示器、混合 DPI、拔屏恢复、全屏应用策略，以及鼠标透明区穿透的长期使用体验尚需专项验证。
- 自启动开关已实现，但未修改本机登录启动配置，也未执行重登验证。
- 尚未进行 2 小时待机/重复交互资源趋势测试。证据中的内存数值只是主进程 RSS 快照，不代表整个应用进程树，也不能作为资源达标结论。
- 未实现语音、Agent 工具、命令执行、3D Renderer、第三方插件安装/沙箱、完整插件热替换和正式安装器。

下一步先用一个真实兼容模型进行体验验证，再集中处理桌面手工验收与角色美术，不提前扩展 Agent 功能。
