# Familiar 灵伴 2.0.0 角色动画与家具美术方案

日期：2026-11-02。状态：**十角色十五类动作、四套家具、食物与玩具已制作并接入**。本文保留美术设计基线，实际交付及验收边界见 [实施与验收记录](25_Familiar_2.0.0实施与验收.md)。产品规则见 [养成与房间方案](23_Familiar_2.0.0养成与房间方案.md)。

当前交付：原七角色共 798 个 SVG 动画帧；新增 DeepSeek 鲸鱼娘、GPT 银发小龙娘、Claude 橙发读书少女共 204 个透明 WebP 帧；34 个物品主图和 4 个床前景 PNG。新增造型为按开工授权制作的首版，不宣称为厂商官方形象。新增角色目录中的 `NOTICE.md` 记录来源与制作说明。

当前家具只提供一个绘制朝向，编辑器不开放旋转；灯光、柜门动画、桌面挂载和家具避障寻路尚未实现。房间使用落地点、地面占地和独立视觉尺寸，床具支持前景遮挡。后文这些扩展表现仍属于设计目标。

目标是让进食、休息、玩耍和长期状态都能从角色动作看出来，同时让小窝具备可收集、可自由组合的箱庭家具。Windows 与 Android 使用同一角色身份和动作含义，按显示尺寸与平台适配表现。

### 1.1 新增角色的参考方向

DeepSeek 沿用户确认的蓝发鲸鱼娘方向制作，饭碗只在吃饭过程中出现；待机、走路、玩耍不强制端碗。蓝白服装、发饰与鲸尾的具体样式需在定稿图中对齐。

## 2. 角色视觉与动画规范

### 2.1 延续现有角色

升级前七个角色来自 `characters/<id>/character.json`，每个角色只有 `idle/greet/happy/think/sleep/drag` 六种动作、各两帧。2.0.0 扩展为十五类动作，每类 6–12 帧，保留柔和描边、浅色块、脸型、配色与关键饰物。

新角色采用相近的轮廓粗细和低对比色块，保留蓝发鲸尾、龙翼龙尾、橙发书本等辨识特征。先做同尺寸站姿并排比较，再完成动作；避免某个角色因复杂头发、翅膀或尾巴占满点击区域。

建议统一透明画布、脚底锚点、可视边界和道具插槽。动画画布可以放大，但不拉伸现有比例；Windows 桌宠、Android 完整悬浮、半头像停靠和房间各自按锚点适配。

### 2.2 首发动作矩阵

建议每个角色交付以下十五种语义动作。阶段三、四的缺粮表现分别使用虚弱和颓废动作，不仅改变整张图片的透明度或颜色。

| 动作 | 类型 | 需要实际画出的变化 | 播放方式 |
| --- | --- | --- | --- |
| 待机 `idle` | 现有升级 | 呼吸、眨眼，耳朵、尾巴、头发或灯光的细微变化 | 低频循环 |
| 问候 `greet` | 现有升级 | 看向用户、挥手或摆动身体 | 单次，回到当前待机 |
| 开心 `happy` | 现有升级 | 面部变亮、抬手、尾巴或翅膀响应 | 单次或短循环 |
| 思考 `think` | 现有升级 | 抬头、扶眼镜、翻书等角色专属动作 | 任务期间循环 |
| 睡眠 `sleep` | 现有升级 | 躺下或蜷坐后的稳定睡姿、呼吸 | 循环，支持床上与无床表现 |
| 拖动 `drag` | 现有升级 | 肢体、衣摆和尾巴对拖动的反应 | 拖动期间展示 |
| 行走 `walk` | 新增 | 脚步或适合该角色的移动姿态，身体同步变化 | 房间移动时循环 |
| 吃饭 `eat` | 新增 | 拿出食物、进食、吞咽、收起道具 | 开始、短循环、结束 |
| 吃饱 `full` | 新增 | 满足表情、拍肚子或轻摆尾巴 | 进食后的单次反馈 |
| 玩耍 `play` | 新增 | 抱、推、追、摆弄玩具；有眼神与肢体变化 | 单次或有边界的循环 |
| 困倦 `drowsy` | 新增 | 打哈欠、揉眼、点头 | 间歇播放 |
| 饥饿 `hungry` | 新增 | 看食盆、摸肚子，动作仍有活力 | 间歇播放 |
| 虚弱 `weak` | 新增 | 眼神和姿势变低落、耳尾下垂、坐卧比例增加 | 低频待机 |
| 颓废 `dejected` | 新增 | 蜷卧、抱膝或靠坐，保留清晰的可交互轮廓 | 低频待机 |
| 恢复 `recover` | 新增 | 抬头、伸懒腰、恢复站姿或精神 | 单次，回到当前状态 |

十个角色共计 150 组动作目标，其中包括对现有动作的重绘完善；这不是 150 张静态图。最终帧数按动作节奏决定。建议待机和睡眠用 4–6 个关键帧，进食和玩耍用 8–12 个关键帧，其余通常 4–8 个；交付逐帧资源、播放时长与循环标记。

需要分动作帧率或帧时长，不能简单把现有全局 1 fps 改为高帧率而让所有动作同速。低频动作保留停顿，界面隐藏时停止绘制；动画暂停不暂停业务状态。最终素材大小、内存和耗电以实际两端测量为准。

### 2.3 动作与业务的关系

睡眠属于生活表现。用户呼出聊天、语音或需要审批时，交互反馈优先，结束后根据真实状态恢复；不会因为动画正在睡觉而延迟处理工作。

拖动等直接操作优先于生活动作。虚弱是持续外观状态，聊天时可通过眼神与姿态保留，但不掩盖思考、回答或待处理提示。切换动作、切换角色和重复播放都不会改变背包、发奖或消费。

进食分为“业务确认已消费并恢复”和“显示吃饭动画”。关闭页面、切换形象或动画资源加载失败时，消费只发生一次；后台自动吃饭也无需依赖动画播放完成。

缺少某个动作的旧角色包按能力降级到近似表情或待机，不能使 Runtime 报错。新增语义、每动作时长和表现变体需要版本化，保留旧包读取路径。

### 2.4 每个角色的交付件

- 正面主姿态、必要侧向姿态、配色与比例说明；明确耳、尾、翼、头发等不可丢失特征。
- 十五类动作及逐帧预览，循环连接自然，头部与落地点不无故跳动。
- 透明背景与清晰轮廓；完整悬浮和半头像模式都有可识别画面。
- 食物与玩具道具、床铺前后遮挡所需信息；道具离开动作后正确收起。
- `Character` 清单、动作时长、循环与降级规则；人物主体和道具资源明确关联。
- 来源、许可、署名及生成或改绘过程记录，与角色资源一起维护。

## 3. 房间与家具设计

### 3.1 统一空间

建议固定 2.5D 箱庭视角，所有家具采用同一透视、比例和地面接触规则。墙面、地板、地毯、普通家具、桌面物件分层，宠物按脚底位置参与遮挡。

套装统一颜色、材质和造型语言，不锁定固定房间布局。用户能把森林灯放到暖木桌旁，也能把鲸鱼娘放进星灯书房。家具按单品出售，套装页面提供组合预览和逐件拥有情况。

建议先制作四套、每套六件，共 24 件可购买家具。下列价格与等级沿用产品草案，尚未定价。

### 3.6 家具交付规范

每件家具提供商店缩略图、房间素材、支持的朝向、落地点、占地范围、遮挡层、可放置面和交互位置。床至少区分角色前后的图层；桌面物件具有稳定的挂载位置。

可旋转物件要有对应视角素材；文字、把手和不对称装饰不能通过简单镜像造成错误。无法进入的床、被墙完全挡住的交互点、悬空家具须在编辑时提示。

装饰动画采用低频变化，不依赖高帧率粒子。灯光、波纹和柜门动作只影响表现；隐藏房间后停止相应绘制。

## 4. 食物与玩具美术

建议首发 4 种食物、3 种玩具；不同角色可使用不同的道具表现，共用食用与物品规则。

| 内容 | 建议价格 | 设计 |
| --- | --- | --- |
| 基础口粮 | 4 | 包装袋和盛装容器；鲸鱼娘为饭碗，方方为能量补给道具 |
| 果盘 | 6 | 柔和水果色块，手动喂食时有拿起、入口动作 |
| 便当 | 8 | 小盒饭，打开后进入进食动作 |
| 精致甜点 | 12 | 小份蛋糕或布丁，配合满足动作 |
| 小球 | 30 | 可推、可抱、可追，适用于全部角色 |
| 纸风车 | 40 | 轻轻转动，角色可伸手拨动 |
| 小积木 | 80 | 短时摆弄和堆叠，用少量造型表达不同过程 |

自动进食的动画可简短，用户主动喂食时展示完整起止动作。特殊食物按等级陆续解锁；基础口粮始终开放。

## 5. 制作与验收顺序

先画现有角色的统一动作样板和鲸鱼娘定稿；GPT、Claude 的参考方向确定后，再制作完整动作。家具先完成暖木套装，验证角色坐卧、遮挡、拖动和缩放后扩展其他三套。

每一批交付都需要在实际角色容器中回放，检查透明边缘、跨帧位置、道具收起、帧速、打断、旧包降级与小尺寸可读性。2.0.0 完整验收覆盖全部十个角色的十五类动作，不能用单个角色的动画演示代替全体交付。

方案评审关注造型与动作；资源导入检查关注清单、尺寸、帧数和路径；运行验收关注真实窗口、Android 悬浮与生命周期。三类完成状态分别记录。
