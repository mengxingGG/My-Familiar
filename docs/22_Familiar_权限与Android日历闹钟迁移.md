# 权限、Android 日历/闹钟与加密迁移

自 1.0.0 起提供。共享 `agent.policy` 是工具授权的唯一所有者，Android 系统权限另外管理。

| 全局模式 | 行为 |
| --- | --- |
| 全自动 | 工具直接执行，仍保留参数、目标版本、路径与系统权限校验 |
| 有限执行 | 默认允许读取和工作区写入；外部写入、手机操作、安装、Shell 与未知 MCP 等按类别规则确认 |
| 审批制度 | 每项先确认，精确用户白名单和当前会话授权可直接执行 |
| 全部拒绝 | 拒绝其他工具，覆盖用户白名单与会话授权 |

四种模式均始终放行联网搜索、内部记忆/日记。内置目录路由也可读取，但实际调用重新走目标工具的权限判断，不能通过目录绕过拒绝。未知 MCP 的自报只读标签不会自动变成固定白名单。

审批可选择“添加白名单”“允许一次”“允许当前会话全部”“拒绝”。白名单匹配目标与参数摘要，忽略不影响操作内容的防重 `operationId`；目标版本、实际操作参数仍参与匹配。会话授权允许该会话不同工具，不能用于其他渠道/会话，换会话、重启、更改模式和撤销时失效。无意图信息的旧式确认只支持一次。

## 日历

通过官方 `CalendarContract` 实现日历列表（含隐藏日历）、本地日历创建、名称/颜色/时区/可见性管理、灵伴自建本地日历删除；查询有文本/日历筛选和分页。日程支持创建、防重、回读、修改、删除、全天、重复系列、已同步系列的单次改期/取消、忙闲与私密级别、提醒方式/提前量、非组织者参会人替换及本地回复状态。写操作核对读取时的版本，使用 Provider 批处理断言并回读结果。

本地日历按[官方 LOCAL 日历方法](https://developer.android.com/reference/android/provider/CalendarContract.Calendars)建立，只以同步身份访问灵伴自己的本地账号。外部或云日历不通过此身份删除。创建/修改邀请的远程送达由账号同步服务负责；本地写入不等于已发送邀请或收到对方回复。

外部复杂重复规则、未同步系列的特殊例外和账号独有功能提供系统日历查看/编辑交接，之后查询核实；不以删建整个系列冒充只改一次。提醒受日历公布的方式/数量限制，通知由日历应用负责。

## 时钟

通过[公开 AlarmClock Intent](https://developer.android.com/reference/android/provider/AlarmClock)接入创建/激活闹钟、每周重复、名称、铃声、振动、解除本次响铃、稍后提醒、倒计时、解除已到期计时器、显示闹钟和计时器列表；可查询系统支持情况、下一次闹钟及设备铃声。相同操作号不会重复交接。

Android 没有公开跨时钟应用的完整闹钟数据库或统一永久删除/编辑 API。已有闹钟的完整列表、永久启停/删除/修改、运行中计时器的暂停/继续/重设，通过显示时钟后使用现有 `android_screen` / `android_action` 无障碍工具逐步完成。`dismiss` 只解除本次响铃，不能声称永久删除重复计划。原生工具返回 `handedOff`，需要观察真实时钟结果；不支持相应 Intent 的应用如实返回不可用。

## 迁移

见 [0.3.1 迁移操作](releases/v0.3.1-migration.md)。导入/导出只能在设置页由用户显式调用，不注册为模型工具，不受模型“全自动”模式隐式触发。文件选取和保存使用 Android 系统选择器；私有缓存和恢复点也只保存密文。
